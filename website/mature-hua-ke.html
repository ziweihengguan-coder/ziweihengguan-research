成熟化科的生成重建

從早期文星母層、五行名額與共同 position／element 骨架，到庚、壬 carrier 的雙版本分支。本文保留《捷覽／全集》與明刊《全書》兩支，不以單一「正表」抹平古本差異。

共同骨架唯一閉合 雙版本並存 carrier 分支 specific adoption 待直證
安星與四化首頁 化權五步成文 化科完整成文

成熟化科目前最可辯護的模型，不是一條把所有古本壓成同一答案的 universal formula，而是「早期母層 → COMMON position selector → COMMON element generator → branch-specific carrier selector」。共同層可以在不讀成熟 carrier 的條件下唯一生成戊水、庚水、壬土；最後星名則依古本分支各自閉合。

研究問題與證據邊界

化科研究必須拆成兩個不同問題：

  1. 生成問題：在不預先餵入成熟化科星名的前提下，能否由早期科層、古典功能表、五行／河洛語法與版本內既存結構，唯一生成成熟兩支共同的位置與元素？
  2. 歷史採用問題：古代編表者是否曾明文說明，自己就是把這些 component 依本文重建的方式組合起來？

前一問題目前可以在已登記 grammar 內唯一閉合；後一問題仍保留 specific adoption 缺口。為避免把算法一致性改寫成作者自述，本文固定使用四層：

早期母層早期科、文星與十變曜 carrier／功能槽。
COMMON position／element決定哪三干改，以及三格各改成什麼五行。
branch carrier在已固定的庚水、壬土上選取各版本最終承載星。
specific historical adoption古人是否明說採用這套 composition；目前仍未直接出土。

定級：COMMON 層屬 TARGET-POSITION-FREE / MATURE-CARRIER-BLIND / GRAMMAR-BOUNDED UNIQUE RECONSTRUCTION。這表示在明列資料、候選與 grammar 中沒有第二個合法解，不等於「古人必然就是如此推導」。

早期母層：文星與十變曜 carrier 環

十變曜提供可計算的 carrier 基底

《星學大成》卷一的十變曜可整理為相對祿母環的十個位置：

祿、暗、福、耗、蔭、貴、刑、印、囚、權
祿=L(g+0)，暗=L(g+1)，福=L(g+2)，…，權=L(g+9)=L(g−1)

這裡的意義不是把成熟化科簡化成固定 shift，而是確認古典星命術本身就存在「固定 carrier 基底＋逐功能 selector」的資料結構。文星、正魁、科名、印星等表又顯示，同一功能在十干上並不必然使用單一 offset，而可以逐干改掛既存 carrier／功能槽。

早期科的直接母骨架是文星

天干甲乙丙丁戊己庚辛壬癸
早期科武曲紫微文昌天機文昌天梁廉貞文曲太陽太陰

早期科反投影到文星母表時，多數干位同位；較集中的差異在庚、辛：庚由文星原取刑槽改取福槽，辛由印槽改取權槽；乙位則保留太極／紫微固定星橋。

因此較節約的早期模型是：

文星逐干 selector ＋ 庚、辛既存功能槽重掛 ＋ 乙位太極／紫微固定星橋

成熟科不是從空白表突然出現，而是對早期母層做有限改寫。

雙版本首先共享的不是星名，而是元素結構

現有古本至少必須同時保留兩個成熟支：

  • 《捷覽／全集》支：庚太陰化科、壬左輔化科。
  • 明刊《全書》支：庚天同化科、壬天府化科。
天干甲乙丙丁戊己庚辛壬癸
早期科武曲紫微文昌天機文昌天梁廉貞文曲太陽太陰
《捷覽／全集》武曲紫微文昌天機右弼天梁太陰文曲左輔太陰
明刊《全書》武曲紫微文昌天機右弼天梁天同文曲天府太陰

兩個成熟支相對早期科共同只改三個位置：

戊、庚、壬

更重要的是，兩支雖在庚、壬 carrier 上不同，十干五行向量卻完全相同：

金、土、金、木、水、土、水、水、土、水
水 4火 0木 1金 2土 3

因此成熟化科應拆成三個問題：先解 position selector，再解 element generator，最後才解 branch-specific carrier selector。從這裡開始，不再用全局整齊度把其中一支裁成抄誤。

科3／8與五行名額：從數學候選到古法同型

河圖五行生數採水1、火2、木3、金4、土5；以研究中既有的「科＝3／8」橋接作為 k=3，在循五意義下得到成熟化科的五行名額：

水4、火0、木1、金2、土3

它具有兩個重要性質：總名額正好為十，而且祿、權、忌或早期七欄並不會任意自然得到同一頻數，因此不是隨意挑出的常見分布。

古法可支持的是 primitive，不是「化科直訣」

宋元明材料可分別支持若干同型操作：

  • 除五取餘可以作五行或位置 selector。
  • remainder state 可以控制實際取用數量。
  • 十干五對、五行與滿週進除可以同時存在。
  • 河圖五行生／成數可以掛成十槽，數值 n 亦存在展開為 n 項的 multiplicity 語法。

所以「科3循五得到名額候選」已不只是現代任意算術，而是由古代取餘、五行映射、數量化與整週進除等 primitive 支持的低自由度 composition。

證據邊界：目前仍不能寫成「某古書明言化科以3／8計算五行名額」。這個特定 composition 尚未直接出土。

火0可用整週進除理解

若先用古典1～5循環表示，可得：

水4、火5、木1、金2、土3

總和為15，而成熟化科只有十干10席。保持各類 mod 5 同餘、非負且總和10時，只能從火5減去一個完整五週期，唯一得到：

水4、火0、木1、金2、土3

因此「火0」不必預設古人使用現代0～4記號，也可以解讀成完整週期進除後無剩餘名額。

COMMON 層真正閉合：12,600 → 9 → 3 → 1

共同層的關鍵測試，是把成熟 carrier 與實際 change mask 延後到 selection 完成後才打開驗證。選擇階段只使用：

  1. 早期科欄；
  2. 早期七欄各干已存在的 carrier／五行 inventory；
  3. 《玄藪》昌曲輔弼 paired placement；
  4. 科3 quota 候選；
  5. minimum-rewrite prior。

第一關：quota 全枚舉，12,600 → 9

所有符合【水4、火0、木1、金2、土3】的十格五行向量共有12,600個。相對早期科的最小 Hamming 改寫距離為3；最小解剩9個，change mask 只有三種：

甲・庚・壬丙・庚・壬戊・庚・壬

quota 已迫使早期兩個火位【庚、壬】退出，但第三個金位仍在甲／丙／戊三選一。

第二關：同干早期元素 inventory，9 → 3

若要求「新元素必須已在該干的早期七欄中有 carrier 實例」，只剩三個候選：

候選改寫
A甲→水、庚→水、壬→土
B丙→水、庚→水、壬→土
C戊→水、庚→水、壬→土

此時尚未讀成熟答案，庚、壬方向已被固定為：

庚水、壬土

第三關：《玄藪》paired-mate gate，3 → 1

三個候選金位的差別是：

  • 甲武曲不屬昌曲輔弼 paired family；
  • 丙文昌雖屬 paired family，但丙干早期七欄沒有右弼；
  • 戊文昌在戊干早期福欄已有右弼，而且右弼屬水。

所以唯一留下：

戊金→水、庚火→水、壬火→土

消融結果

條件剩餘解作用
全部保留1唯一戊水／庚水／壬土
拔同干元素 inventory2戊仍定，但庚／壬水土可互換
拔 paired-mate gate3第三金位回甲／丙／戊三選一

COMMON 結論：paired-mate gate 負責唯一選出戊；同干早期元素 inventory 負責定向庚水／壬土。最後才揭開成熟兩支驗證，兩者五行向量均10／10命中，實際 change mask 也都是【戊、庚、壬】。

庚水分支：G0 與 G1 不是同一條 selector

COMMON 只固定「庚科＝水」，不決定最後是太陰還是天同。庚位必須與庚忌聯動，因為兩個主要版本的庚模組分別為：

G0《捷覽／全集》太陰科／天同忌
G1明刊《全書》天同科／天相忌

G0：太陰科／天同忌

在既存的庚×【太陰、天同、天相】三候選池中，科／忌有序排列共有6種。兩個 gate 分別把6種壓到2種：

  1. 古本直接存在庚生人逢忌與天同的 specific 關聯，鎖定天同忌；
  2. 庚祿為太陽，配合古典日月 pair，取太陰作科。

兩者交集唯一得到：

G0＝太陰科／天同忌

第一條屬 branch 層目前較強的 specific direct evidence；第二條仍是把日月 pair primitive 操作化到庚科的研究者 composition。

G1：天同科／天相忌

G1不能沿用G0直證。較合理的解法是把它視為來源受限的「編輯型 remount」：

  1. 科位優先重用早期同干既存 carrier，唯一指向庚福＝天同；
  2. 新插入忌 carrier 必須提高《全書》固定化氣主星覆蓋，唯一指向天相。

交集唯一得到：

G1＝天同科／天相忌

但《全書》自身下游判語仍大量保留G0型天同忌，這更像四化歌／編表層的局部整編，而不是全書所有判語同步重算。

G1 定級：SOURCE-BOUNDED EDITORIAL REMOUNT RECONSTRUCTION / NOT DIRECT ANCIENT SELECTOR。目前沒有古文直說「把天同從福／忌重掛到科，再把天相插入忌」。

壬土分支：R0 與 R1 各有不同優先級

COMMON 已固定「壬科＝土」。固定星土 carrier universe 為：

紫微天梁左輔天府

同行四化不重可以把候選由4壓成【左輔、天府】；但最終消融顯示，這只應保留為 target-free prefilter／structural validation，因為 R0、R1 各自的 branch selector 不靠它也可直接從完整四顆土 carrier 中唯一取值。

R0：《捷覽／全集》壬左輔科

共同科已存在辛文曲，而《玄藪》辰順 paired family 為：

文曲（時）／左輔（月日）

COMMON 已先獨立固定壬位必須改成土，因此完成辰順 paired family 時，從完整土 carrier universe 可以直接唯一取：

R0＝左輔

這與早期「先知道壬左輔，再回頭套配對」不同：position／element 已由 COMMON 層獨立鎖定，paired family 只負責 carrier closure。

R1：明刊《全書》壬天府科

R1 有兩條彼此獨立、各自都足夠唯一天府的 selector：

  1. 壬權已固定紫微，古典紫府 dual-anchor mate 唯一取天府；
  2. 由R0→R1看固定化氣主星覆蓋增量，左輔增量0、天府增量1，因此唯一天府。

既有材料另有壬×天府關聯，《全書》天府章亦保留壬生人及可承科權祿的相容語義。這些都支持「天府是壬土層可用 carrier」，但仍不是「壬化科所以取天府」的 direct sentence。

R1＝天府

R0偏重 paired-family completion，R1偏重紫府 dual-anchor／覆蓋優先級；兩支使用不同編整方向，正是「版本分支」而非單一正表／錯表關係。

兩個成熟古本支如何完整閉合

《捷覽／全集》支：G0R0

COMMON【戊水、庚水、壬土】 → G0【庚太陰科／天同忌】 → R0【壬左輔科】

得到《捷覽／全集》的成熟化科支。

明刊《全書》支：G1R1

COMMON【戊水、庚水、壬土】 → G1【庚天同科／天相忌】 → R1【壬天府科】

得到明刊《全書》的成熟化科支。

G 與 R 是可分模組，形式上可組成 G0R0、G0R1、G1R0、G1R1；但「算法上可組合」不代表四組都具有同年代、同古本或同文本見證。本文只把有主要古本對應的 G0R0 與 G1R1 列為本輪成熟支。

版本學原則：不再追求一條 universal carrier selector 把所有版本壓成同一答案。共同位置／元素由 COMMON 層處理，carrier 則在版本分支內各自閉合。

成熟化科並非「只有數學擬合」，因為多數 component 有可追溯的古典來源；但也不能說「歷史生成公式已直接出土」，因為關鍵 composition 仍缺少編表者的直接自述或過渡表。

為何不再追求一張「最整齊的唯一正表」

研究早期曾以「十星／十角色不重、昌曲左右完整、同干四化不重」比較不同庚×壬組合，並一度讓較整齊的組合取得較高優先級。最終雙版本消融後，這種用法必須降級，原因有三：

  1. 《捷覽／全集》與明刊《全書》兩支都是真實待解資料，不能以現代整齊度裁掉其中一支。
  2. 庚 G 與壬 R 是兩個可分版本模組，不宜以單一全局整齊指標當 universal generator。
  3. 同行四化不重在壬位只屬 target-free prefilter／validation，不是 R0／R1 最終不可消融 selector。

方法論收斂：不是「找出最整齊的一張成熟化科表」，而是「先重建兩支共同的 position／element，再讓 carrier 在版本分支內各自閉合」。

停止條件：只有四類證據值得重開 provenance

成熟化科的算法層與版本分支已足以成文，後續不再泛找另一條更漂亮的公式。只有下列四類 specific composition 真正出現時，才值得重開歷史 provenance：

  1. 前1581或1581系文本直接把「科3／8取餘」套到成熟化科五行 quota；
  2. 直接把《玄藪》昌曲輔弼 paired family 用作戊／壬成熟科重掛的句子或表；
  3. 直接說明 G1「天同→科、天相→忌」的編輯型 remount；
  4. 直接說明壬科為何 R0 取左輔、R1 取天府的 branch-specific composition。

在未命中以上證據前：

  • 不再泛搜另一條 universal formula；
  • 不再用新的整齊性 constraint 重裁古本；
  • 不把一般取餘、配對、重掛 primitive 重複計成 mature-Ke specific adoption。

結論與來源

成熟化科目前最可辯護的生成模型，是四層結構：

早期科／文星母層 → COMMON position selector → COMMON element generator → branch-specific carrier selector

COMMON 層在不讀成熟 carrier、不預餵戊庚壬 change mask 的條件下，唯一生成：

戊水、庚水、壬土

完整五行向量與名額為：

金、土、金、木、水、土、水、水、土、水
水 4火 0木 1金 2土 3

《捷覽／全集》支再由 G0、R0 得到【庚太陰科／天同忌、壬左輔科】；明刊《全書》支由 G1、R1 得到【庚天同科／天相忌、壬天府科】。兩支在各自 branch grammar 內都可以唯一閉合，因此歷史上應並存保留，不以一支裁另一支為誤。

同時，本文不把「唯一生成重建」改寫成「古人已明文留下完整算法」。直接古文最強的是早期母層、古典取餘／配對／重掛 primitive，以及 G0 的庚天同逢忌；科3／8 quota、paired repair 到成熟化科、G1 editorial remount、R0／R1 specific carrier composition 仍保留歷史採用缺口。

最終研究狀態：算法／結構重建已封板，版本雙支已封板，轉入正式成文；specific provenance 只等待四類決勝原文，不再泛搜公式。

主要古籍與材料

《新刻纂集紫微斗數捷覽》及《全集》系統。保存成熟化科的 G0R0 支：庚太陰科、壬左輔科，並提供成熟四化、主星與安星語境。

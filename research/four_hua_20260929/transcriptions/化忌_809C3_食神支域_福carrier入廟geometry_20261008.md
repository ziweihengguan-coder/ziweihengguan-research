# §809-C3 食神支域 × 早期福 carrier 入廟 geometry：6/7 相容，但只能當第一層 filter

日期：2026-10-08（臺灣時間）

## 一、問題

使用者提出一個重要方法判斷：

> **早期《紫微數》福欄應該不是十顆任意死表，而應可由某種規則計算。**

§809-C2 已直接證明 early-Ziwei 同一文本會使用：

> 條件／功能 role → old-name carrier

的 selector grammar；但其 worked example 以年支三合組為 index，尚不能生成十干福欄。

本節不再枚舉任意十干 relation，也不讀成熟化忌；改取一條真正前1581、且明文把【食神／福祿】落到地支 geometry 的古法，測它能否成為福欄的第一層 selector。

## 二、1578《三命通會》直接存在五組食神支域

卷五〈論食神〉先明說：

> 【食神者，十干福祿之會。】

後又把十干依五組列成：

> 甲乙食丙丁，加寅卯巳午之上；  
> 丙丁食戊己，加辰戌丑未之上；  
> 戊己食庚辛，加巳午申酉之上；  
> 庚辛食壬癸，加申酉亥子之上；  
> 壬癸食甲乙，加亥子寅卯之上。

因此可直接正規化為：

| 干組 | 食神生旺支域 |
|---|---|
| 甲乙 | 寅、卯、巳、午 |
| 丙丁 | 辰、戌、丑、未 |
| 戊己 | 巳、午、申、酉 |
| 庚辛 | 申、酉、亥、子 |
| 壬癸 | 亥、子、寅、卯 |

這不是研究者為福欄量身擬合的分組，而是萬民英1578文本自己的五組 geometry。

來源：
- 《三命通會》卷五公開文本：`https://www.shidianguji.com/zh/book/HY1521/chapter/1knwennx4qwp8`

## 三、early-Ziwei 同一文本已有 old-name 星宿入廟 geometry

《中天太極紫微數秘訣／玄藪》在七欄表後直接列〈星宿入廟詩〉，其中可固定十四個主體 old-name 的入廟集合，例如：

- 天暴＝寅、申；
- 鳳凰＝酉、戌、亥、申；
- 天雷＝卯、戌；
- 天宜＝寅、亥、未、酉；
- 喧蛇＝子、丑、寅；
- 進神＝卯、申、辰、巳；
- 白衣＝亥、子、卯；
- 其餘太極、天驛、太常、天庫、暗金、五鬼、天相亦可同樣列出。

這是 early-Ziwei 自己的 carrier geometry，不是成熟四化反推。

## 四、把福欄七顆主星 raw carrier 投入五組食神支域

福欄 raw row：

> 甲天宜、乙白衣、丙天暴、丁進神、戊八座、己龍池、庚鳳凰、辛鳳閣、壬天雷、癸喧蛇。

其中八座、龍池、鳳閣在 early-Ziwei 另有月日／時安置法，不能拿 static 入廟集合做同尺度比較；故先測其餘七顆。

結果：

| 干 | 福 raw carrier | 對應食神支域 | 是否有交集 |
|---|---|---|---|
| 甲 | 天宜 | 寅卯巳午 | YES：寅 |
| 乙 | 白衣 | 寅卯巳午 | YES：卯 |
| 丙 | 天暴 | 辰戌丑未 | **NO** |
| 丁 | 進神 | 辰戌丑未 | YES：辰 |
| 庚 | 鳳凰 | 申酉亥子 | YES：申／酉／亥 |
| 壬 | 天雷 | 亥子寅卯 | YES：卯 |
| 癸 | 喧蛇 | 亥子寅卯 | YES：子／寅 |

即：

> **6/7 compatibility**

唯一零交集：

> **丙天暴**

## 五、但 6/7 不能升格為 selector：同域候選太多

這一步必須做負控。

每個四支食神 domain 與 early-Ziwei 十四個 static carrier 比較，能相交的 carrier 數量為：

- 甲乙域：11/14；
- 丙丁域：11/14；
- 戊己域：9/14；
- 庚辛域：11/14；
- 壬癸域：13/14。

因此「有交集」本身很寬鬆。

按 overlap 數量排名：

- **庚鳳凰**是唯一明顯的 rank-1 target；
- 甲天宜、乙白衣、壬天雷等都不是該域最強唯一候選；
- 丙天暴甚至完全不入其食神 domain。

所以最嚴格判語只能是：

> **食神支域對福欄提供一個真古法的五對 geometry filter，但不能唯一選 carrier。**

## 六、這輪仍然很重要：它第一次把「福欄可計算」縮成兩層

目前最節約模型不是：

> 十干 → 一張舊表 shift → 福欄

而是：

> **十干五對**
> → **食神／福祿 geometry 或 functional state**
> → **第二層 carrier selector**
> → **early-Ziwei old-name**
> → **fixed star**

C3 已找到一個合格的第一層候選：

> 【五對食神支域】

但第二層仍缺。

而三顆 auxiliary：

> 戊八座／己龍池／辛鳳閣

尤其重要，因為它們不屬於 static 十四主星入廟 selector；它們顯示第二層很可能不是純「找某宮位的主星」，而是：

> **functional type → unified fixed-star lexicon**

即可以跨主星／輔曜 namespace 取 carrier。

## 七、目前下一個最有辨識力的問題

不要再問：

> 「哪一個 branch 與福星相交？」

因為 C3 已證太寬。

下一步只值得問：

> **在同一 early-Ziwei 文本內，有沒有一組功能型別能把每個年干的五對 state 進一步唯一指定為天宜／白衣／天暴／進神／八座／龍池／鳳凰／鳳閣／天雷／喧蛇？**

優先抽取 target carrier 自身的明示功能詞：

- 龍池＝科名星；
- 鳳閣＝科甲星；
- 八座＝華蓋星；
- 天雷＝掌兵權；
- 進神＝加官進職、福中星；
- 白衣＝兵權／權柄；
- 其餘逐顆只用 early-Ziwei 原文，不先借成熟《全書》的後出「化氣」字典。

若這十顆能形成一個低重複的 functional-type vector，再與前1581十干功能表交叉，才可能真正得到：

> **stem → type → carrier**

的 calculable 福欄。

## 八、§809-C3 最終判語

> **「福欄應可計算」這個方向得到一個新的真古法正控，但尚未閉合。1578《三命通會》直接保存十干五對的食神生旺支域；與 early-Ziwei〈星宿入廟詩〉交叉時，福欄七顆 static 主星 carrier 有6/7至少一支相容，證明五對 geometry 並非完全無關。然而每個支域通常同時容納9–13顆 old-name carrier，故它只能是第一層 filter，不能唯一選星；丙天暴更是硬例外。真正缺口已縮成第二層【functional state → unified fixed-star carrier】selector，尤其必須同時解釋八座、龍池、鳳閣三顆 auxiliary carrier。**

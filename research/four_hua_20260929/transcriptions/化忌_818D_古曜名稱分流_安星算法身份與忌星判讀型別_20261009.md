# §818-D｜古曜名稱分流與安星算法身份：龍池／鳳閣對文曲／文昌的可核演算（2026-10-09）

**狀態：來源型別／安星算法正控完成；「化囚／天元忌星→生年固定化忌」specific rule 仍 OPEN。** 承§818-C；本節不以成熟化忌十干表作任何計算輸入，不聲稱跨文本同型操作等於可證的直接傳承。

## 1. 本輪真正新增的驗證入口

先前 §815 已注意《紫微數》「安龍池水星＝文曲」「安鳳閣金星＝文昌」的字面附著，但尚未把**《捷覽》重新使用龍池、鳳閣作不同安星法**列成具體反證。現在可把「舊曜體如何取得固定紫微星身份」的檢驗方法，從單純字形／五行配對提升為**安星算法指紋**：起點宮、方向、輸入時間型別、輸出位置、受用對象，全部具備才談同一操作。

### 2. 不看成熟化忌表，先完成來源端 12×12 狀態演算

固定十二宮位置以子=0，辰=4，戌=10；`h` 是子至亥的**出生時支**序位，`y` 是子至亥的**出生年支**序位。

- 舊龍池＝文曲：`(4+h) mod 12`。
- 舊鳳閣＝文昌：`(10-h) mod 12`。
- 《捷覽》文曲、文昌：仍取上述兩式的 **h**。
- 《捷覽》新龍池：`(4+y) mod 12`；新鳳閣：`(10-y) mod 12`。

在 **144 種年支×時支的形式組合**（不是144份歷史命盤樣本）中：

- **舊龍池／鳳閣的安置位置＝《捷覽》文曲／文昌：144／144。** 這是一條獨立於「化忌答案」的 *operator-preserving star correspondence* 實例。
- **舊龍池／鳳閣的位置＝《捷覽》同名新龍池／鳳閣：僅12／144。** 等值當且僅當 `h=y`，其餘132種不同。絕不可因「龍池」同名而偷換其依生年與依生時的算法。
- 可辨識算例：**甲子年丑時**，舊龍池＝《捷覽》文曲在巳、舊鳳閣＝《捷覽》文昌在酉；新龍池在辰、新鳳閣在戌。

可重跑的來源端檢查：`node research/four_hua_20260929/ji_818_d_operational_identity_source_only_20261009.js`，**17/17 PASS**（含下述三台／八座追加正控）。程式直接讀本機《玄藪》轉錄及乙亥字本校讀，另按上述**公開點校人工抽錄**《捷覽》關鍵句作固定 fixtures；不連網抓取原葉，不讀成熟化忌表，不聲稱17項為17個獨立原件校證。

### 2-B. 第二組獨立操作：三台／八座的「月＋日合算」在《捷覽》拆為兩段

另見《玄藪》兩條：
- 「安三台：左輔土星，又官星」，實際操作是 **辰宮起正月順至生月，再由該宮起初一順至生日**。
- 「安八座：右弼水星，又華蓋星」，操作是 **戌宮起正月逆至生月，再逆數生日**。

《捷覽》把這個計算**因式分解**成：
1. 〈安左右〉先獨立安左輔、右弼，分別為辰順生月、戌逆生月。
2. 〈安三台八座〉再以左輔為初一起點順數生日得三台、以右弼為初一起點逆數生日得八座。原訣是「三台左辅顺初一……八座右弼逆初一」。

以 **m＝生月1–12，d＝生日1–30**（只測非閏月常規序位）計：

- 《玄藪》三台：`(辰 + m−1 + d−1) mod 12`；《捷覽》三台：`(左輔 + d−1) mod 12`，而左輔＝`辰+m−1`，故完全相等。
- 《玄藪》八座：`(戌 − (m−1) − (d−1)) mod 12`；《捷覽》八座：`(右弼 − (d−1)) mod 12`，而右弼＝`戌−(m−1)`，故完全相等。

**12×30＝360 種普通月日形式組合，兩對安星位置均 360/360 相同。** 這是來源端運算恆等式，不是360份歷史命例；古本的閏月處理與《捷覽》算例校補仍須另分層。譬如二月初五，舊三台與新三台同在酉；舊八座與新八座同在巳，新左輔卻在巳、新右弼在酉。故「舊文稱左輔／右弼」不足以推斷後來同名固定星仍在同一位置，必須辨識**整條操作鏈**。

**文本缺陷負控：** 《捷覽》八座逐字算例內的「右弼在寅、初五逆數至午」在點校頁有腳註指出當作「戌」，因為寅逆五位為戌；本輪採**安星口訣＋通用算法**而非將該錯例當作正確資料。此例只支持保存操作、可經分段重述，不直接證明其文本先後或轉抄支系。來源同前公開《捷覽》點校卷一安星段落及本機《玄藪》轉錄〈安三台／安八座〉。

### 3. 此例能證的程度與不能證的程度

**成立：** 兩系可以保留相同的計算機制而更換主體名稱；一個古名也能在較晚類型的斗數文本中轉為另一顆以不同輸入安置的輔星。這比「某五行舊曜正好有一顆同名固定星」更具有排除多義的能力。相同安置算法為**結構對應證據**，是否為直接源流傳授，仍須版本譜系與時間層次佐證。

**不成立：** 從這兩對星直接類推「化囚必可經同一方法改成年度化忌」，因為文曲文昌算法使用**生時**、新龍池鳳閣使用**生年支**、十變化囚則使用**生年干**，三者本來屬不同輸入型別；不可互換。

### 4. 與《捷覽》年度化忌真正連接時，必須新增一個 type gate

《捷覽》卷一〈安禄权科忌四化诀〉先列「甲廉破武阳，乙机梁微月……」及其解釋：「甲年生人……太阳下安忌」與「乙年……太阴下安化忌」。這是**年干→固定星身份直接指定**，尚未讀到它由古典「天元忌星」轉表的算例或 caller。

該書〈化忌星論〉又說「太陽在寅卯辰巳化忌，太陰在酉戌亥子化忌，反為福論」，對廉貞在亥化忌亦依火入水鄉、水命等作解，另〈忌星入限斷訣〉說「忌星入廟反為良」。**這是對已被指定為化忌之星的吉凶再評價，不是把化忌 carrier 改掛另一顆星。**

需要嚴守三個映射層：
1. `F(生年干, 古十變位次) -> 古典曜體`（《星學大成》卷1／30，已證）。
2. `R(古典曜體, 源端觸發條件, 書系/版本) -> 成熟紫微固定星`（真正未知）。
3. `E(固定星已化忌, 宮位, 五行, 時令, 煞吉配置...) -> 有條件吉凶`（《捷覽》下游評斷）；**E不得冒充R**。

若考察的早期《捷覽》已直接編有 `J(年干) -> 固定星`，也須容許一種歷史假說：**直接編表／文本重寫**，而不是預設必有每次排盤都在執行舊曜→新星的物理轉換程序。兩說需文獻比較，不能由今日公式優美決定。

### 5. 接下來限定搜尋的 source-side 目標

以**算法指紋**審核《紫微數》《玄藪》及《捷覽》更多條目：記下每條 `input(year stem/year branch/month/day/hour/palace/mansion)`、起點、方向、選星者與輸出，先找**有文獻直接指定**的跨名安星對應。對涉及化囚、天元忌、祿、刑、印等的條目，再搜是否出現使用**生年干與十變曜，並宣告如何接回固定星**的同型 caller。須把「結果吉凶」與「取誰當化忌」分欄，不能因「反為福」誤作 carrier exchange。

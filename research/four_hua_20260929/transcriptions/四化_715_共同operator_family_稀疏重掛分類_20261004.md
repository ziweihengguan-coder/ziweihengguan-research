# §715 四化共同 operator：同為「穩定骨架＋稀疏重掛」，但權／科／忌屬三種不同 rewrite 型

日期：2026-10-04

## 目的

化權在§714已封板，因此本輪不再追816來源，而把祿、權、科、忌統一拆成同一分析 schema：

【母表／穩定骨架 → carrier pool → selector → orientation → local rewrite → validation】

只使用已封存的古表、成熟表與既有重建結果，不重新用成熟target選參數。

## 一、化祿：母表本身

成熟祿與早期祿10/10一致，可直接作底層母表。

- 母表：祿欄本身。
- carrier pool：不變。
- selector：無二次selector。
- local rewrite：0格。

祿因此是四欄中唯一不需要成熟期二次稀疏重掛者。

## 二、化權：7/10骨架＋3格「保量閉合置換」

依§713封板模型：

【祿前移一干 → 廉退紫入】

先得到7/10基底：

【破、紫、機、同、陰、貪、武、陽、巨、梁】

成熟權為：

【破、梁、機、同、陰、貪、武、陽、紫、巨】

差異只在【乙、壬、癸】三格：

- 來源：【紫、巨、梁】
- 目標：【梁、紫、巨】

三個carrier完全相同，只改位置；局部carrier overlap＝3/3，global pool delta＝0。

所以權的local rewrite是標準的：

【3-carrier closed permutation】

再由北極亥子丑scope＋紫微逆行給出8→1→6方向。

## 三、化科：同樣7/10骨架＋3格，但屬「全替換」

早期科骨架：

【武、紫、昌、機、昌、梁、廉、曲、陽、陰】

成熟科通行支：

【武、紫、昌、機、弼、梁、陰、曲、輔、陰】

同位仍恰好7/10，差異為【戊、庚、壬】三格：

- 來源：【文昌、廉貞、太陽】
- 目標：【右弼、太陰、左輔】
- 局部carrier overlap＝0/3。
- 全表multiset必須移出【文昌、廉貞、太陽】各一，移入【右弼、太陰、左輔】各一。

元素流：

【金、火、火】 → 【水、水、土】

所以化科雖與權同樣呈現「7+3」，卻不是閉合cycle，而是：

【3-slot carrier replacement】

其selector仍應分層理解為：
- 科3/8的五行名額候選；
- §413成對carrier結構；
- 戊／庚／壬position與版本carrier再分開。

《捷覽／全集》支與南陽堂支在庚科、壬科雖換星，但五行保持10/10一致，故科仍以【position → element → carrier】三層模型最穩。

## 四、化忌：6/10骨架＋4格「部分移位＋兩出兩入」

早期福槽：

【陰、巨、廉、梁、弼、曲、同、昌、武、貪】

成熟通行忌：

【陽、陰、廉、巨、機、曲、同、昌、武、貪】

同位6/10；後五干【己庚辛壬癸】5/5凍結。

真正差異只在【甲、乙、丁、戊】：

- 來源：【太陰、巨門、天梁、右弼】
- 目標：【太陽、太陰、巨門、天機】

其中太陰、巨門兩顆仍留在改動區，但改位置；另有：
- 移出：【天梁、右弼】
- 移入：【太陽、天機】

故忌不是純cycle，也不是像科的全替換，而是：

【2-carrier remount + 2-carrier pool swap】

目前最強歷史模型仍是：
【早期福槽位置骨架 × 印星十曜池 → 前五干受限重排】

但唯一化仍部分依賴後世《乾元秘旨》解碼，因此歷史證據等級低於已封板化權。

## 五、共同架構與不能強行統一之處

本輪最重要的新結論：

> 四化確實可以統一到更高階的編表架構：
> 【母表／穩定骨架 → selector → 必要時pool／element正規化 → 稀疏local remount → validation】。

但不能再向下硬壓成同一種local operator。

三個派生欄分別是：

1. 權：3格保量閉合置換，carrier overlap 3/3。
2. 科：3格全替換，carrier overlap 0/3。
3. 忌：4格混合，carrier overlap 2/4，且2出2入。

因此【7+3】雖同時出現在權與科，但只能視為共同「稀疏重寫架構」，不能宣稱共同三循環公式。

## 六、下一步§716

下一輪最值得直接做的，不是再搜一條四化總公式，而是把三種rewrite放入同一消融矩陣：

- 權：P3 = closed 3-cycle；
- 科：R3 = 3-slot replacement；
- 忌：H4 = 2-remount + 2-pool-swap。

優先驗證忌的H4是否為最小分解：
1. 若只允許位置重排，是否必然失敗；
2. 若只允許pool swap而不搬太陰／巨門，是否仍失敗；
3. 是否恰好需要「2顆保留carrier移位＋2顆carrier替換」；
4. 再檢查這三種primitive是否已可構成一個最小的四化operator family字典。

若成立，四化共同語法就可從「每欄一條公式」提升為【有限rewrite primitive＋各化selector】模型。

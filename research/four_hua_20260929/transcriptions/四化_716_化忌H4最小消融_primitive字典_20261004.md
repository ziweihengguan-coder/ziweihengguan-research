# §716 化忌 H4 最小消融：carrier-conserving 最小分解與四化 Sparse Rewrite primitive 字典

日期：2026-10-04

## 目的

§715 將三個派生欄初步分類為：

- 權 P3：3-carrier closed permutation；
- 科 R3：3-slot replacement；
- 忌 H4：2-remount + 2-pool-swap。

本輪只處理兩個問題：

1. 忌的 H4 是否真是不可再約簡的最小分解；
2. P3／R3／H4 是否可再上收成更小的共同 primitive 字典。

## 一、先固定「最小」的語義

早期福槽：

【太陰、巨門、廉貞、天梁、右弼、文曲、天同、文昌、武曲、貪狼】

成熟通行忌：

【太陽、太陰、廉貞、巨門、天機、文曲、天同、文昌、武曲、貪狼】

直接同位保留 6/10：

- 丙廉貞
- 己文曲
- 庚天同
- 辛文昌
- 壬武曲
- 癸貪狼

四個變動槽為甲、乙、丁、戊。

但「四格不同」本身不能推出 H4，因為若完全不要求保存舊 carrier，直接把甲乙丁戊四槽全部 replacement，R4 也能精確得到成熟忌。

因此本輪把「最小」嚴格定義為：

> 先最小化 global carrier pool 的刪除／新增量；在此 minimum-pool-churn 條件下，再最大化既有 carrier 的保存，只把必要的共享 carrier 改位。

也就是 carrier-conserving canonical decomposition，而不是單純比較 changed-slot 數量。

## 二、global pool delta 強迫至少 2 REPLACE

早期福槽全表 carrier multiset 與成熟忌相比：

移出：

【天梁、右弼】

移入：

【太陽、天機】

其餘 8 個 carrier 皆保留。

所以任何忠實反映全局 carrier pool 變化的分解，都至少需要：

【2 REPLACE】

純 permutation 不可能，因為 source 與 target 的 global multiset 不同。

這是一個直接的 multiset lower bound，不依賴任何歷史 selector。

## 三、minimum-pool-churn 下又強迫 2 REMOUNT

8 個保留 carrier 中，有 6 個原位不動；另兩個雖仍存在，位置已改：

- 太陰：甲 → 乙
- 巨門：乙 → 丁

如果堅持只做全局真正必要的 2 次 REPLACE，那麼太陰、巨門不能被刪除後重加，必須直接保存 identity 並改位。

因此再強迫：

【2 REMOUNT】

得到 canonical H4：

【2 REMOUNT + 2 REPLACE】

具體為：

REMOUNT：
- 太陰：甲 → 乙
- 巨門：乙 → 丁

REPLACE：
- 移出天梁、右弼
- 移入太陽、天機

## 四、完整 conservation frontier：H4 不是唯一 4-action 描述，但它 pool churn 最小

腳本枚舉出的 trade-off：

| REMOUNT | 最少 REPLACE | 總 changed-token actions |
|---:|---:|---:|
| 0 | 4 | 4 |
| 1 | 3 | 4 |
| 2 | 2 | 4 |

所以：

- R4 = 0 remount + 4 replacement，可以精確命中；
- 1+3 也可以作形式描述；
- H4 = 2+2 也是 4 actions。

三者若只看「總共動幾個 token」同為 4，故不能宣稱 H4 是唯一 slot-edit 最小解。

但只有 H4 的 REPLACE 數等於真實 global pool delta=2，沒有把本來仍存在的太陰／巨門假裝刪掉再重加。

因此最準確的結論是：

> H4 是【carrier-conserving／minimum-pool-churn】意義下的 canonical 最小分解；不是不加限制時唯一的 4-slot rewrite。

這個修正比 §715 原本直接稱「最小形狀」更嚴格。

## 五、權／科／忌其實可上收成同一 Sparse Rewrite S(m,r)

同一 canonical decomposition 程式同時重算三欄：

### 權

祿前移＋廉退紫入基底 → 成熟權：

- direct hold = 7
- remount = 3
- replacement = 0
- global pool delta = 0

因此：

【P3 = S(3,0) + closed-cycle】

三顆保留 carrier：
- 天梁：癸 → 乙
- 紫微：乙 → 壬
- 巨門：壬 → 癸

且組成閉合三循環。

### 科

早期科 → 成熟科：

- direct hold = 7
- remount = 0
- replacement = 3
- global pool delta = 3

因此：

【R3 = S(0,3)】

移出：
【文昌、廉貞、太陽】

移入：
【右弼、太陰、左輔】

### 忌

早期福 → 成熟忌：

- direct hold = 6
- remount = 2
- replacement = 2
- global pool delta = 2

因此：

【H4 = S(2,2)】

## 六、primitive 字典可再縮成兩個真正原子

到這一步，P3／R3／H4 不必視為三種彼此無關的 primitive。

真正最小的 rewrite atoms 只需兩個：

### REMOUNT

carrier identity 不變，只改落位。

- 不改 global carrier multiset。
- 權大量使用。
- 忌保留太陰／巨門時使用。

### REPLACE

移出一個 carrier、移入一個新 carrier。

- global pool delta 增加一對。
- 科全部由此構成。
- 忌只需要兩次。

所以可以統一寫成：

【Sparse Rewrite S(m,r)】

其中：
- m = remount 數；
- r = replacement 數。

四欄現階段：

- 祿 = S(0,0)
- 權 = S(3,0) + closed-cycle / orientation
- 科 = S(0,3)
- 忌 = S(2,2)

closed-cycle、orientation、selector 不是第三種 carrier 原子，而是施加於 REMOUNT／REPLACE 之上的結構限制。

這比「P3／R3／H4 三 primitive」更小。

## 七、selector 消融：印星 pool 是強約束，後五凍結有辨識力但不唯一化

沿用既有：

【福槽 × 印星十曜池 × 變五行候選】

不使用成熟 target 選參數，只做候選數量消融。

兩支克全部允許時：

### 不凍結後五、不限制印星 pool

候選：

【78,732】

### 凍結後五、不限制印星 pool

候選：

【324】

### 不凍結後五、限制印星 pool

候選：

【4】

成熟忌在其中。

### 凍結後五、限制印星 pool

候選：

【2】

成熟忌在其中。

### 凍結後五＋印星 pool＋每條只取第一列克

候選：

【1】

唯一為成熟忌。

所以：

1. 【印星十曜 pool】是最強的低退化約束之一；
2. 【後五干凍結】在 pool 固定後把 4 → 2，有辨識力，但不能單獨唯一化；
3. 【第一列克】把 2 → 1，但依賴較晚《乾元秘旨》的句序，不能因此升格為明代原訣。

這與先前證據分級一致。

## 八、§716 最終結論

本輪可正式升級的不是「化忌公式已破解」，而是 operator family 的形式化：

> 四化派生欄可統一為【穩定骨架 + Sparse Rewrite S(m,r) + selector/orientation/validation】。

carrier-level 最小 atoms 只需：

【REMOUNT】
【REPLACE】

而目前三個派生欄分別落在：

- 權：S(3,0)
- 科：S(0,3)
- 忌：S(2,2)

祿則為 S(0,0)。

對忌而言：

> H4 = S(2,2) 是 minimum-pool-churn／carrier-conserving 的 canonical decomposition；R4 雖可精確重寫四槽，但會額外刪除再重加太陰、巨門，屬非保守描述。

## 九、下一步 §717

下一輪最值得直接做【mother-table／骨架的全候選 MDL 負控】。

目前祿→權、早期科→科、早期福→忌的 mother 選擇，歷史上各自有理由，但現在既然已建立 S(m,r)，就應把早期七欄全部逐一當成候選母表，對成熟權／科／忌計算：

- direct holds；
- remount；
- replacement；
- changed slots；
- global pool delta；
- 是否符合已知古 pool／位置約束。

目的不是用成熟 target 反推公式，而是做 negative control：

> 檢查目前選定的【祿／早期科／福】是否真的是各自最簡、Pareto 最優或在古約束下唯一合理的 mother，而不是研究者先選母表後才得到漂亮 sparse rewrite。

如果這一關通過，四化共同 operator family 才不只是事後分類，而具有更強的最小描述長度（MDL）支持。

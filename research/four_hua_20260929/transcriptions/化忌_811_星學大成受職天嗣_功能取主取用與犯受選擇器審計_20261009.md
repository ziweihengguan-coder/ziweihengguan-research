# §811　《星學大成》〈論受職星〉／〈論天嗣〉：功能取曜 caller 及犯受取端審計

日期：2026-10-09。承接同日《化忌_星學大成崇勳原句_祿宮主直接調用與五虎遁資訊負控_20261009.md》。**§810-A／B與既有計分器保持原封不動**；本輪不用早期福欄、不讀成熟化忌目標作算子篩選、不另設按干自由 lookup，也不拿清代《乾元秘旨》填年代孔。

## 一、研究問題與直接結論

檢查同一部《星學大成》是否明文保存一個可共用的 **「選取某一功能星」選擇條件**，而非另一種可將十干重新編碼的算式。重點：〈論受職星〉、〈論天嗣〉，並對讀〈論崇勳〉、〈論歲殿〉、〈論催官〉、卷三〈論吉凶星〉及卷十三主客、三方主與刑忌。

**結論：同書保存多種實際可執行的 target-to-carrier／house-to-lord caller，且明確區分曜名、功能及主客作用；但 caller 是由「指定功能」或「指定宮位」個別決定，未找到在祿主、宮主、加害者、受害者之間通用且固定選出化忌承載星的 independent selector。** 本輪不新增任何 mature Ji 匹配分數。此為來源類型檢查與限制辨識，不是十干生成完成。

## 二、七個同書操作：原句、輸入、輸出、選擇條件

| 本文位置、原文錨點 | 型別化輸入 → 輸出 | 何者決定「選哪個」 | 能否不看盤面直接定十干唯一曜？ |
| --- | --- | --- | --- |
| 卷一〈論天嗣〉：「欲推天嗣者即其變曜中化貴者是也」；「甲人祿是火，己人祿是月」 | 年干 → 既有十變曜「化貴」carrier | **明文指定目標功能「天嗣」調用「化貴」**；其夫妻六合解說提供理由 | 對「天嗣」本身有十干唯一舊曜表；無「忌調用貴」指令 |
| 卷二〈論受職星〉：「取本宫對宫上逆數至太嵗」；例「戊申人…寅…甲…庚…以水受職星」 | 原文指定的本宮／對宮、太歲宮、計數方向／起干 → 得干庚 → 水曜 | **取對宮、逆數到太歲**；算例閉合至庚水，但非祿母原干直查 | **未定**。本宮／地盤起算的一般化仍待異本；唯一算例未交代如何因出生年干戊改變選擇 |
| 卷二〈論崇勳〉：「只看他禄宫主是也」及「有主居其上則曰崇勲」 | 原干祿位 → 宮主候選；**宮主實際在祿宮** → 崇勳成立 | 先取祿位的**宮主**，後以實際曜位判格 | 候選型別可算，但格局成立需要星曆／盤面；不等於忌星 |
| 卷一〈論歲殿〉：「命天元干神宫主」；「丙辰生人從辰上起甲數至午見丙」 | 生年干支、起甲方位、數至目標干 → 歲殿所在，再檢查候選功能曜是否居其上 | 先選宮，後查福主、權財、命／身／官／科名等**多個容許角色** | 選的是功能位置與合格條件，並非唯一指定一顆星 |
| 卷一〈論催官星〉：「此星與祿主相為催尅」；甲火祿見金催、乙孛祿見水催 | 原干祿主 → 依催剋關係取候選催官曜 | 目標「催官」明示取祿主相對功能 | 本文有十干催官曜表，但沒有催官＝化忌之名義繼承 |
| 卷三〈論吉凶星歌〉：「名…」「用…福權財禄囚煞忌刑」 | 原曜身分、時令／作用 → 吉凶功能評定 | **作用不可由星名固定決定**，必論善惡之「用」 | 否；「忌」用法不等於已立十干紫微化忌新表 |
| 卷十三「三方主星化為刑忌」及「賓破主者，他來尅我」 | 三方主（含宮位）、十變功能與主客強弱／季節／實際關係 → 主或賓被判害 | 取三方主是先前盤面法，犯受方向由賓我相對關係區分 | 否；不同盤面、遠近、得時會使評判不同 |

卷十三「三方主星化為刑忌」的源文已在同日〈化忌_聿斯三方主與十變連用_年干角色不可代犯受審計〉登記；本輪只加以**對讀 caller 類型**，不冒充新發現。卷三用「忌」與卷十三用「刑忌」是作用／判語的詞，**不能僅憑同字就認定與紫微成熟化忌表同一 namespace**。

## 三、〈論受職星〉算例驗算與歧義

傳本記：「戊申人自地盤寅上逆數甲至太嵗上得庚以水受職星也。」

按字面算例：申的對宮為寅；甲在寅逆序至申恰六移，序列為寅甲→丑乙→子丙→亥丁→戌戊→酉己→申庚；年干庚在同書祿母環為水，與「以水受職星」相符。**此僅重現原例，不是補出全部十干受職星母表。**

最強負控是**不要把這條當作獨立的十干 caller**：若強行一般化為「對每一太歲支一律從其對宮起甲，逆數六位」，則永遠落庚／水，不論原年干；這只說明該無補充假設的字面一般化沒有十干辨識力，**不能反證原作者另有地盤、本宮、安命或起干的未見補充規則**。另一方面，戊申例並未示範同為申支而年干不同時怎樣變曜，且「本宮」究指哪個基準待異本文句、同卷立命法核對。不可為迎合化忌答案任補起甲點、改數向或使年干分路。

另原文「受職星臨本生太歲宜為貴人」是**後置臨宮評估**，與「計算受職曜之身分」是兩個不同步驟。不能把「取受職」的「受」字當「加害者／受害者」之受端操作；名稱同字不是型別相同。

## 四、共同骨架與缺失之 selector

本輪可抽象為：

1. **取目標 T**：天嗣／受職／崇勳／催官／歲殿／三方主（原文各自點名）。
2. **選擇 input namespace**：年干祿母之變曜功能、宮位與宮主、數宮所得天干、或具體盤面主客關係。
3. **按 T 的規則取 carrier／位置**：例如 T=天嗣取化貴，T=崇勳取祿宮主，T=受職按對宮逆數再轉曜。
4. **盤面檢查（有則保留）**：居於祿宮、臨太歲、居歲殿、三方主化刑忌、賓來剋主等。

**共享的是具名目標決定何種 caller 的程式語法，而不是已發現一個共用 selector 可以替化忌決定取主、取犯或取受。** 這比單純天干換碼更強（實際有選擇操作），也比「完整祿母生成化忌」仍少一個決定性的 specific target declaration／固定取端法。

特别分開四個不能混的「受」：

- 〈受職星〉的受：具名職位功能星；
- 〈論天嗣〉的取：功能角色 remount；
- 主客「賓來剋主」中的受剋：盤面關係；
- 十變曜「所忌」「刑囚」：功能評價／role；不自動轉成固定化忌。

## 五、可否形成下一輪可反駁預測？

目前尚**無合格的新化忌 candidate selector**可事前封存並測 G0/G1/G2。若要真正推出獨立預測，下輪至少必須找到：

- **caller gate**：文獻指明「化忌／忌用」為何固定取天嗣式某變曜 role、受職式某宮所推干曜、祿宮主、或賓／主哪一端；也可以是具等價性的明確算法，不要求字面必須叫「化忌」；
- **input closure gate**：規則在年干固定、出生月日時／日月星曆變動時仍固定輸出同一 carrier，或有源證支持如何消去額外盤面參數；
- **remount gate**：若取舊曜須接紫微固定主星／昌曲名，需有獨立於成熟表的選擇映射；「能推出十個不同鍵」不得代替映射；
- **history gate**：先核可用原刻／獨立版本。現核本機 Kanripo WYG 四庫本與線上維基文庫四庫本一致，**未目驗1563原刻此句**；作者年代錨不是逐字存世證明。

先達成前述 gate，才能另立事前新候選、再做庚兩說及不同早期版本目標對照。本輪不藉缺一條定向口訣而停止有據的公式研究，但也不把盤面條件刪掉。
